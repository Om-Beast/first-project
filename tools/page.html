Findings

One readiness label hides three decisions.

Prototype access, production entitlement and public-app distribution are different gates. The research keeps them separate, because each calls for a different next step.

Auth

OAuth is common.
Its scope matters.

__OAUTH__ apps document OAuth on an investigated API or native MCP surface. API keys and tokens often provide the simpler own-account prototype; customer installations may require OAuth.

Gating

Paid does not
mean partner-only.

Squarespace exposes API keys on eligible paid plans. Copper permits API access on trials. A plan upgrade is a different dependency from getting a DealCloud tenant.

MCP

A server's presence
doesn't prove action coverage.

Mailchimp's official MCP searches documentation. Help Scout's new MCP connections are read-only. Copper's official server is announced with a waitlist.

The agent / the proof

A small research system, with a paper trail.

Hosted coding agents ran live research over the exact 100-app list. The portable runner and immutable artifacts make the work inspectable, reproducible offline and extendable with a fresh provider run.

Discover

Find primary evidence

Search authentication, credential issuance, API references and MCP separately. Resolve the exact product before researching it.

Extract

Bind claims to URLs

Use a strict record schema and per-field evidence. Keep missing or contradictory facts explicit instead of filling gaps from memory.

Challenge

Run fresh doc checks

Freeze the first pass, audit a fixed sample and let another agent challenge the result. Keep the misses and adjudications.

Publish

Compute the case study

Validate the exact set of 100 apps, derive every number from JSON and generate one self-contained HTML page with exports.

Live mode needs OPENAI_API_KEY and a compatible model. It checkpoints each app, uses live web search and rejects evidence URLs missing from the consulted-source trace. Local API keys never belong in this page.

What actually ran

Live source discovery and document audits ran through hosted Codex agents. The offline reproduction path and local validation checks ran on the preserved results.

The portable OpenAI Responses provider adapter is implemented and covered by offline transport tests. A direct provider-API run was not executed here. This distinction prevents a replay from being presented as fresh research.

Scope, limitations and what this does not establish
  • This is a point-in-time documentation snapshot from 24 November 2026. API entitlements, auth and MCP rollout can change.
  • The sample is purposive, four apps per research batch with category coverage. It is not a statistically random population sample, and the corrected score reuses the reviewed sources.
  • Some claims rely on indexed primary-source snippets where pages would not open. Evidence entries distinguish search from opened sources. A URL proves provenance, not that every inference is correct.
  • No credentials were generated and no authenticated vendor API calls were performed. Free trials, tenant availability and quotas were checked through documentation.
  • Official MCP status includes announcements, previews and documentation servers. It does not establish production availability, write coverage, Composio catalog presence or an integration gap.
  • Fanbasis, Paygent Connect, iPayX and other unresolved fields remain visible. Paid access is not silently relabeled as partnership gating.
  • Composio's authenticated toolkit registry was not queried in this run. An optional SDK adapter is provided; this report makes no net-new catalog-gap claims.
  • AI assistance was used for research, implementation and review. Three additional primary-document checks are recorded separately as AI review. Independent human review has not been performed.
Recommended next steps / analyst inference

Three queues, with different owners.

Prioritize the access path before implementation. These are prototype candidates and investigation priorities, not claims that Composio lacks a toolkit.

Engineering

Start with clear access

Use a documented self-serve path and a small read-only action set. Confirm production rights before expanding.

Partnerships / customer success

Secure the tenant or approval

Code alone cannot create customer access or replace a vendor's production review. Ask for a scoped test account.

Research / product judgment

Resolve before committing

Confirm the product, credential path and contradictory documentation. Keep local tools on a separate runtime path.
